# E3结论：小幅单次收益，不能声称稳定有效

预先假设和控制变量见docs/e2_decision.md；数值表和配对区间见docs/e3_report.md。训练、全量推理、评分、分析均成功结束，核心E0–E3闭环已完成。

E1→E3：715→726/1034正确，EX69.15%→70.21%，+1.06个百分点；32条改对，21条改错。hard从100/174→104/174，extra-hard仍87/166，合并困难子集187/340→191/340（55.00%→56.18%）。easy增加1条、medium增加6条，整体收益不只来自困难桶。

代价：可执行SQL从920→910条（88.97%→88.01%），无效schema引用启发式标签112→124。schema linking标签245→238、JOIN155→151，变化较小且这些是重叠词法诊断。零生成失败、零输出截断。

20数据库聚类bootstrap的总体EX差值95%区间约[-0.31,+2.49]个百分点，包含0。一个训练seed、dev指导方法选择、数据库相关性和单库EX局限都限制结论。正确表述是“同预算下本轮小幅提高EX，但稳定性未证实且可执行率退化”，不能写成显著、普遍或无代价改进。

## 实际改进和退化的原因不总是复杂结构

- dev:54（pets_1，hard）问女生养了多少dog。E1和E3的JOIN结构相同，关键差异是字面量“Dog”→“dog”，E3通过EX。这是值大小写改善，不足以证明复杂JOIN推理能力提升。
- dev:132（car_1，hard）询问3缸车型最大马力及make。E1输出Model，E3输出Make，后者与Gold结果匹配，属于列语义选择改善。
- dev:64（pets_1）E1正确，E3把pettype写成pet_type，SQLite报no such column。加权没有消除schema标识符错误。
- dev:90（car_1）E3把ContId归到countries别名，报T1.contid不存在，E1正确。复杂度代理与列归属能力并非一一对应。

完整原始SQL和错误都保留在results/predictions/e1_dev.jsonl、e3_dev.jsonl及逐条evaluation；没有人工修正模型输出。这些案例是离线解释，不能进入未来推理Prompt作为Gold线索。

## 决策

保留这一轮，不按dev追加搜索最优权重或挑checkpoint。E1的标准SFT带来主要收益（相对E0+18.38个百分点）；E3更适合展示假设、严格控制、真实结果与局限，而非包装为原创先进算法。下一步的独立价值在E4资源比较与E5推理对照，暂不扩大训练数据或更换模型。
