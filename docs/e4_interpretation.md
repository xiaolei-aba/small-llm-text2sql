# E4：QLoRA的实际权衡

完整7000条/438步，沿用E1顺序、输入和监督token、均匀loss及优化器参数。改变冻结底座为NF4双重量化，并使用标准kbit准备和BF16计算；非量化参数dtype也变化，不能称为只改变存储位宽的严格消融。

全量1034 dev：713条正确（68.96%），E1为715条（69.15%）；48条从错变对、50条从对变错，净少2条。可执行906条（87.62%），E1为920条（88.97%）。数据库聚类95% EX差值区间约[-2.99,+2.83]个百分点，无法据此证明等效、无损或稳定退化。

训练allocated峰值4.516→3.213GB，降低28.86%；循环时间49.02→62.17分钟，增加26.84%。原生逐条生成平均延迟1671.54→2961.39ms、输出吞吐19.16→10.72 token/s。不同输出长度与硬件状态也影响速度，不能视为固定token轨迹的内核速度比较。E1恢复曾影响reserved缓存，不用reserved差值替代allocated的对照结论。

在本机8GB条件下普通LoRA已经可运行，因此QLoRA的价值是提供更低训练allocated的选择，而非本项目中唯一可训练方式。它没有同时改善所有指标。量化底座参与训练和推理，未单独分离两者的质量影响；单seed与单库EX限制仍在。

证据：[对照报告](e4_report.md)、[训练报告](e4_training_report.md)、[错误对照](e4_comparison.md)，对应results中的真实JSON与逐条评分。生成、评分、分析命令均退出0；零生成失败与截断。
