# E2 证据与 E3 预先决策

本决策在 E1 全量评分完成后、E3 训练前固定。来源：results/e2_error_analysis.json、docs/e2_error_analysis.md、results/e1_dev_summary.json。

E1 单库 EX 715/1034（69.15%），比 E0 增加 190 条；配对改进 248 条、退化 58 条。以数据库为聚类单位的 10000 次 seed42 bootstrap，EX 差值区间约 +13.60 至 +24.34 个百分点，仅条件于这两个训练结果；不能代替多 seed 验证。

残余 319 条错误中：easy 33/248、medium 133/446、hard 74/174、extra-hard 79/166。后两桶错误率 42.53%/47.59%，合计占错误的 47.96%，而占评测样本 32.88%。这为检验结构复杂样本加权提供依据，但不证明复杂度是唯一原因。

多标签启发式还显示 schema linking 245、列选择 227、表选择 156、JOIN 155、无效 schema 引用 112。标签重叠且不等于人工因果归因。实际核对的 dev:6/7/12 仍把 singer.song_name 归给 singer_in_concert 的别名，导致不存在的列；其问题并非训练中缺少 JOIN，而是列归属混淆。dev:75 少 DISTINCT，SQL 可执行但重复行改变结果；dev:110 漏输出 maker id，但简单词集合比较未识别，因为 id 在 JOIN/GROUP BY 中也出现。这说明自动诊断需要案例核验，不能当作精确错误标签。

## 只做一组复杂度 loss 加权

假设：在同样的训练覆盖和计算预算下，适度增加复杂 SQL 样本的优化贡献，可提高 hard/extra-hard EX，并可能改善总体 EX。采用官方结构难度作为 train-only 代理，不用 dev Gold 构造训练样本或选 Prompt 的表列。

原始权重 easy=1、medium=1、hard=2、extra=2。train 计数为1694、2777、1461、1068；按全部7000条的均值9529/7000归一化。每个微批先计算 SQL/EOS token 均值 CE，再乘该样本归一化权重；累积 batch 内按实际样本数求均值。不按当前 batch 的权重和再次归一化，因此这是固定全局加权目标。raw loss 和 weighted objective 分别记录。

与 E1 完全相同：基础权重、LoRA 初始化 seed42、样本来源/顺序、每条曝光一次、序列与监督 token 总数、438步、AdamW、学习率/调度、累积、梯度裁剪、精度、监督边界、生成与评分。E3 从原始底座训练新 adapter，不继续训练 E1。相对贡献改变是自变量；梯度范数及裁剪频率可能随之改变，不能保证每一步更新尺度相同。

选择 loss 加权而不是重采样，是为了保留完全相同的覆盖率和 token 预算。系数2为本次单一、预先固定的适度对照，不按 dev 搜索最优系数，不在看结果后改成其他方法。E1 已是全部权重为1的控制组，无须重复其训练。

主要指标是全量 EX；关注 hard+extra-hard 的合并 EX（固定340条），并同时报告 easy/medium 退化、可执行率、schema/JOIN 启发式错误变化。若总体或困难子集没有改善，记录负结果；不根据局部最好桶宣布成功。

## 限制

方法选择参考了 dev 反馈，因此 E3 是探索性比较，不是独立测试集结论；一个 seed 不能证明稳定提升。难度是结构代理，未必对准语义 schema linking 瓶颈，甚至可能鼓励多余复杂结构。不得把该简单加权称为原创算法或声称在尚未运行前有效。

资源比较补充：E1经历了断点恢复，E3当前为连续运行；缓存分配器历史不完全相同。即使reserved出现差异，也不能归因于loss加权节省显存。allocated与reserved均原样报告，训练计时另披露重算与停机。
